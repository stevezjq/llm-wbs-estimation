# MiniMind 课程问答助手 MVP 需求规格说明书

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 系统类型 | LLM 应用原型 |
| 技术基座 | MiniMind（约 64M 参数，原生 PyTorch 实现） |

## 1. 背景与用户角色

《人工智能导论》课程每年约 300 人选修，助教需重复回答大量相似问题，包括概念解释、作业要求、实验环境配置等。现拟基于课程开源项目 MiniMind 建设一个课程问答助手 MVP：以 MiniMind 的 SFT 权重为基线，用课程素材做领域微调，提供网页端问答服务，检验小参数模型在垂直领域问答上的可行性与成本。

系统用户角色如下：

- 学生：通过网页提问，查看历史会话；
- 助教：维护课程素材，抽查回答质量，记录错误案例；
- 课程教师：最终验收与试用评估。

## 2. 功能需求

| 编号 | 名称 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 领域数据构建 | 从课程讲义、FAQ、历年答疑记录中约 5000 条原始素材出发，完成清洗、去重、纠错与格式转换，产出 1500–3000 条 SFT 训练样本（JSONL） | 高 |
| F2 | 领域微调 | 以 MiniMind 主线 64M 模型的 full_sft 权重为基线，使用 LoRA 训练领域适配权重，训练脚本兼容 MiniMind 原有工程结构 | 高 |
| F3 | 评估集与评测协议 | 构建不少于 200 题的评估集，覆盖概念解释、作业要求、实验步骤三类；实现自动评测脚本（关键词命中与语义相似度），并制定人工评分标准（1–5 分）与抽检流程 | 高 |
| F4 | 推理服务 | 封装 HTTP 接口，支持流式输出、多轮会话（携带课程上下文）、按 IP 的基础限流 | 高 |
| F5 | 对话前端 | Web 对话页面，支持历史会话列表，回答中展示所引用的讲义章节编号 | 中 |
| F6 | 部署与监控 | 单张 RTX 3090 容器化部署，开机自启；提供基础监控面板，展示 QPS、首 token 延迟、显存占用 | 中 |
| F7 | 版本管理 | 每次训练记录数据快照、超参配置与权重校验和，支持在历史版本间切换与回滚 | 中 |

## 3. 非功能需求

- **N1 效果门槛**：在评估集上，自动评测指标须超过基线模型 15 个百分点，教师人工评分均值不低于 3.5/5；未达标须继续训练迭代。
- **N2 响应性能**：首 token 延迟 p95 低于 2 秒，支持 10 个并发会话。
- **N3 数据合规**：提问日志脱敏后存储，去除学号与姓名；课程素材、训练数据与模型权重不得离开校内网络。
- **N4 可维护性**：课程素材更新后，可在 30 分钟内完成增量重训并切换上线。
- **N5 资源约束**：训练与推理共用同一张 RTX 3090，训练只能安排在夜间窗口（22:00 至次日 07:00）进行，白天须保证推理服务可用。
- **N6 文档**：交付全链路技术文档，覆盖数据构建、训练、评测、部署的完整复现步骤。

## 4. 约束与不做范围

- C1 基座模型固定为 MiniMind 主线约 64M 参数版本，不允许更换更大参数模型。
- C2 采用纯微调方案，不引入 RAG 检索，不接外部知识库。
- C3 不做多模态、语音与移动端 App，不做 RLHF/DPO 对齐训练。
- C4 素材仅限课程讲义、FAQ 与历年答疑，不引入公开语料；若素材数量或质量不足，由助教补充采集。

## 5. 交付与验收

- D1 交付内容：数据处理与训练脚本、模型权重、推理服务、前端页面与技术文档。
- D2 效果验收：在评估集上达到 N1 门槛，并由教师随机抽检 50 题做人工评分。
- D3 试用验收：10 名学生试用 1 周，收集问题清单，所有问题须在正式验收前完成修复。
