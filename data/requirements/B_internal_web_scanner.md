# 内网 Web 漏洞扫描器 需求规格说明书

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 系统类型 | 内网安全工具 |
| 适用范围 | 单位内部 Web 系统安全自查 |

## 1. 背景与用户角色

单位内网现运行约 100 个 Web 系统，按等级保护要求需定期开展安全自查并留存记录。现有商业扫描器存在授权点位不足、检测规则无法按单位业务定制的问题，拟自建一套轻量 Web 漏洞扫描器，由安全工程师发起扫描并对结果进行人工复核，形成可归档的检测报告。

系统用户角色如下：

- 安全工程师：维护资产信息，发起与复核扫描任务，出具检测报告；
- 系统管理员：负责部署、账号管理与运行维护；
- 被测系统责任人：接收整改通知并反馈整改结果，仅线下沟通，系统不设该角色账号。

## 2. 功能需求

| 编号 | 名称 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 资产台账 | 维护域名/IP、所属系统、责任人、系统等级；支持从 CSV 模板批量导入，支持资产分组 | 高 |
| F2 | 站点信息收集 | 对目标站点爬取 URL，识别表单、参数与常见接口路径，探测常见敏感目录 | 高 |
| F3 | 被动扫描 | 以代理模式接收工程师日常访问流量，仅记录不注入，对请求与响应进行被动特征检测 | 中 |
| F4 | 主动检测 | 内置 SQL 注入、XSS、目录遍历、弱口令等检测插件；支持以 YAML 规则文件编写自定义检测逻辑，新增规则不修改引擎代码 | 高 |
| F5 | 任务编排 | 新建扫描任务时选择资产、插件集与并发数；支持暂停、恢复、终止；可设置扫描时段与请求速率上限 | 高 |
| F6 | 结果管理与报告 | 对漏洞按 URL 与参数去重，按严重/高/中/低分级，支持人工标记误报；导出 PDF 与 Excel 报告 | 高 |
| F7 | 复扫验证 | 对已整改资产发起复扫，自动更新漏洞状态（已修复/仍存在/无法验证） | 中 |

## 3. 非功能需求

- **N1 检测效果**：对验收靶场中 50 个已知漏洞的检出率不低于 80%，误报率不高于 10%，达标前不得上线。
- **N2 扫描器自身安全**：扫描凭据加密存储；管理端仅允许内网访问；管理端自身须通过一轮渗透测试复核。
- **N3 合规**：扫描任务、结果复核与整改确认全过程需审计留痕；输出的报告与记录须能支撑单位年度等保测评中的安全测试证据要求。
- **N4 性能与稳定性**：单任务并发 10，单站点扫描时长不超过 30 分钟；扫描不得使用破坏性载荷，不得导致被测业务不可用。
- **N5 规则可扩展**：规则库与检测引擎分离，规则文件支持热加载。
- **N6 部署环境**：部署在完全隔离的内网环境，无外网访问，无法在线安装依赖，需提供离线安装包与后续升级方案。
- **N7 文档**：交付《使用手册》与《规则编写指南》，后者需覆盖 YAML 规则字段说明与编写示例。

## 4. 约束与不做范围

- C1 不得使用任何外部 SaaS 扫描服务，扫描流量不得离开内网。
- C2 不做全网段资产自动发现、不做流量镜像与 IDS、不做移动端。
- C3 验收所需靶场由项目组自行搭建，基于开源漏洞环境构建，覆盖 50 个已知漏洞，含 Web 常见漏洞类型。

## 5. 交付与验收

- D1 交付内容：可运行系统、源代码、离线部署包与文档。
- D2 靶场验收：依据靶场测评报告核对检出率与误报率。
- D3 真实环境试扫：选取 3 个真实内网系统试扫并人工复核结果；试扫中暴露的登录态处理、特殊框架兼容等问题须在验收前完成适配。
