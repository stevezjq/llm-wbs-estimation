# 论文写作前结果底稿（2026-11-25）

本文件汇总可写入报告的最终数字、结论与效度说明。所有数字来自 `analysis/summary.md` 与 `analysis/*.csv`；原始记录见 `runs/runs.jsonl`（105 条 = 105 个 case×prompt×repeat 组，P3 另有 15 条 stage1，共 120 次 API 调用）。

## 1. 实验口径

- 模型：`deepseek-chat`（OpenAI 兼容端点 `https://api.deepseek.com`），temperature 0.7，max_tokens 4096。
- 案例：A 设备预约（专家 19 包/132h）、B 内网漏洞扫描器（22 包/160h）、C MiniMind 问答 MVP（21 包/128h）。
- 方案：P0 朴素表 / P1 结构化 JSON / P2 多角色清单 / P3 两阶段 / P4 三点 / P5 交付物对账 / P6 对账 + 隐性工作保留。每方案每案例重复 5 次。
- 真值口径：单熟手、净人工投入、无风险/管理缓冲；三点区间 a≤m≤b，hours=m。
- 指标：总量符号误差、APE、CV、任务数×单任务工时分解、类别层 log 比值、埋点关键词提及率、三点区间覆盖率、log-log 规模回归、基线敏感性。

## 3. 四个核心发现

### 发现 1：朴素提示（P0）灾难性高估且极不稳定
- 修正解析后总量：A 520–1080h（真值 132）、B 988–2304h（160）、C 280–588h（128）。
- 模型原文甚至明确按“5 人团队 12–14 周”排期（B 约 2300 人时），属于口径漂移/范围膨胀，不是同一口径下的算术误差。
- CV 32–38%，5 次重复差异可达 2 倍以上。P0 同时放大包数（×1.82）与单包工时（×2.97）。

### 发现 2：结构化提示把单包工时校准到专家水平，但包数膨胀导致 +25%–63% 高估
- P1–P4 的单任务工时比为 1.01–1.05（专家 6.1–7.3h/包，模型 6.9–7.1h/包），总量比 1.34–1.55。
- log 分解：P1/P2 约 95–97% 的总量偏差来自任务条数，单包工时贡献仅 3–5%。
- 解释：模型把同一交付物拆成多个包，每个包仍按“常规规模”估 6–8h，造成结构性重复计工。这是比“模型不会估时”更具体的缺陷。

### 发现 3：只压包数会牺牲隐性工作；P6 才能兼顾
- P5 用“一个交付物一个包”把包数压到基准以下（×0.82），总量接近真值（APE 5.3/8.0/12.3%），但 C 案例提及率降至 84%，漏掉 C-11 增量切换、C-12 GPU 夜间调度、C-15 补充采集。
- P6 增加“六类隐性工作必须独立成包、不受合并规则约束”，包数回到 ×0.94、单包 ×1.11，总量比 1.04；APE 降至 8.8/7.1/3.3%，C 提及率回到 99%。
- 结论：**估算精度与覆盖完整性存在张力**；单纯追求总量准确会诱导模型合并/省略难估工作。

### 发现 4：区间估计与类别结构
- P4 三点区间覆盖率 A 80%、B 40%、C 80%，宽度 108–115%；B 的乐观值总和 164.8h 已高于真值 160h，属于乐观偏差，不是区间太窄。
- P5/P6 覆盖率均为 100%，宽度 103–117%；P6 的 a/b 总和：A 103/210、B 122/265、C 96/204。
- P6 单独类别偏差：DEP +41%、PM +31%、SEC +19%、DES +10%、REQ +0.4%、COD −1.3%、TEST −0.3%、DOC −8.7%。总量准确但类别间存在再分配（部署/管理/安全偏高，文档偏低）。
- 规模效应：log(LLM/专家) 对 log(专家工时) 斜率 −0.060，R²=0.018（n=144），未发现稳定规模效应。
- 高估分布：P0–P4 几乎全部为高估（±5% 阈值）；P5/P6 出现低估与“接近”，说明误差方向不再系统性偏向高估。

## 5. 基线敏感性（必须写入局限/讨论）

专家真值整体 ×k 后，P0 仍高估 +121%～+483%（k=1.5），结论稳健；结构化方案对 k 敏感：

- k=1.25：P1 偏差 +16%～+30%，P4 +10%～+16%，P6 −22%～−26%（转为低估）。
- k=1.5：P1 +5%～+8%，P4 −17%～−4%，P6 −35%～−38%。

因此报告应表述为“相对于偏紧的单熟手基线”，而不是“LLM 绝对高估”。B 案例尤其明显：160h 覆盖爬虫、被动代理、4 类插件、靶场与合规，属于很紧的下界。

## 6. 效度与限制（报告第 5/6 节可直接用）

1. **模型替换**：原计划 `deepseek-flash`，实测为推理模型（300 completion tokens 全为 reasoning、正文空、忽略 temperature），改为 `deepseek-chat`；记录中 model 字段均为 deepseek-chat。
2. **真值单源**：专家 WBS 由同一人（本实验）自估并复核，存在同源偏差；B 基线偏紧；未做多人独立估算。
3. **post-hoc 提示设计**：P5/P6 在观察 P1–P4/P5 错误后改写，并在同一组 A/B/C 上验证，缺少留出案例，存在过拟合风险；需在报告中明确。
4. **提及率是上界**：关键词命中不等于单列工作包，可能被测试/文档任务顺带提及；已做 P5/P6 逐项证据核查，C 的 P5 漏项为真实漏项。
5. **P0 解析**：初版解析把“合计/模块标题/空交付物”行当任务，已修正并用 `reparse_p0.py` 重解析；修正前后差异保留在 `runs/runs.jsonl.bak`。
6. **样本规模**：单模型、单温度、5 次重复、3 个中文案例；不能外推到其他模型/语言/领域。
7. **任务级不可配对**：采用类别层+总量+结构分解，未做逐任务配对；这是方法选择，不是遗漏。
8. **P3 两阶段**：stage1 只拆解不估时，stage2 基于 stage1 JSON 估时；分析取 stage2。

## 8. 一句话结论（可作摘要末句）

在统一“单熟手、净人工、无缓冲”口径下，朴素提示会因范围膨胀与粒度失控产生 2–8 倍高估；结构化提示把单包工时校准到专家水平，但包数膨胀仍带来 25%–63% 高估；只有在对账包数的同时强制保留隐性工作（P6），才能把三案例 APE 压到 3%–9%，并保持 95%–100% 的要点覆盖与 100% 的三点区间覆盖。
