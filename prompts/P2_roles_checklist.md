# P2 多角色强制清单 v1.0

你是资深软件项目经理。请把下面的需求拆解为 WBS 工作包，并为每个工作包估算工时。

【需求】
{{REQUIREMENT}}

【估算口径】
- 单位为人时（person-hour），指完成该工作包的净人工投入。
- `hours` 为最可能值，不含风险缓冲、管理缓冲和返工预留。
- 不考虑组织级因素（采购、法务、跨部门协调）。

【估时前的强制自检】
依次以以下视角审阅需求，逐项确认是否需要对应工作包，**不得默认省略**：
1. 需求与设计视角：需求澄清、验收口径、架构与数据设计、接口定义。
2. 开发视角：全部功能实现、前后端之间的内部联调。
3. 测试视角：功能测试、兼容性测试、性能测试、缺陷修复、试运行整改。
4. 安全与合规视角：审计留痕、越权与口令安全、安全测试/评审、合规材料。
5. 交付与运维视角：用户文档、离线或容器化部署、监控与备份、版本管理。
6. 管理视角：例会、进度跟踪、评审组织。
若某类确实不适用，须在对应任务的 `assumptions` 或全局说明中写明理由。

【拆解要求】
1. 每个工作包必须有明确、可验收的交付物。
2. 常规工作包不超过 8 人时；确属不可再分的时间块可至 10 人时，并在 `assumptions` 说明原因。
3. 只覆盖需求中真实存在的工作，不臆造需求之外的功能。

【输出格式】
只输出一个合法 JSON 对象，不要输出解释性文字，不要使用 Markdown 代码围栏。
